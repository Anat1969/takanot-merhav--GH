# DATA-MODEL: ‏data/takanot.json

`data/takanot.json` הוא מקור האמת היחיד. הקובץ חולץ בסקריפט מתוך `takanot-merhav.html` (PARAMS, FIX, RULES, SCENES, PARTS, SYN), בלי הקלדה ידנית של ערכים.

## מבנה עליון

```
{
  meta, params, rules, scenes, parts, fixtures, sceneFixtures, synonyms
}
```

## meta

| שדה | תיאור |
| --- | --- |
| `title` | שם האפליקציה |
| `regulation` | שם התקנות המלא |
| `source` | `{ name, url }`: הנוסח המחייב (נבו) |
| `extractedFrom` | קובץ המקור של החילוץ |
| `note` | הסתייגות שמוצגת בממשק |

## params: ערכים רגולטוריים

מפתח: מזהה ב־snake_case. זה המזהה שמופיע בגוף התמצית כ־`{key}`.

| שדה | סוג | תיאור |
| --- | --- | --- |
| `label` | string | שם הפרמטר בעברית |
| `op` | `>=` `<=` `>` `<` `=` | כיוון הדרישה. אופרטור השוואה מסמן מגבלה, שמוצגת באדום |
| `value` | number | הערך |
| `unit` | `m` `m2` `ratio` `count` | יחידה |
| `rule` | string | מספר הסעיף שהפרמטר שייך אליו. חייב להופיע ב־`rules` |
| `verified` | boolean | `false` עד שנבדק מול הנוסח הרשמי |
| `source` | object או null | ‏null עד לאימות. אחרי אימות: `{ checkedBy, checkedAt, citation }` |

### כלל האימות

- כל 14 הפרמטרים מתחילים ב־`"verified": false, "source": null`.
- רק אדם משנה ל־`true`, ובאותו קומיט ממלא את `source`. הבדיקה תכשיל `verified: true` כשאין `source`.
- כל ערך עם `verified: false` מוצג בממשק עם התג "לאימות", בטקסט וגם בטבלת הכותרת (מספר הערכים שעוד לא אומתו בסצנה).

### עיצוב ערך לתצוגה

| unit | כלל | דוגמה |
| --- | --- | --- |
| `m`, ערך קטן מ־1 | ס״מ, עם ספרה עשרונית אחת אם צריך | 0.175 ← 17.5 ס״מ |
| `m`, ערך 1 ומעלה | מטרים, שתי ספרות אחרי הנקודה | 2.5 ← 2.50 מ׳ |
| `m2` | כמות שהוא, ואחריו מ״ר | 8 מ״ר |
| `ratio` | אחוזים, מעוגל | 0.1 ← 10% |
| `count` | כמות שהוא | 18 |

אופרטור לתצוגה: `>=` מוצג ≥, ו־`<=` מוצג ≤.

## rules: תמציות סעיפים

מפתח: מספר הסעיף. רק סעיפים שיש להם תמצית והמחשה.

| שדה | תיאור |
| --- | --- |
| `title` | כותרת הסעיף |
| `kind` | "דרישה מדידה" או "מגבלה מדידה" |
| `scene` | מזהה הסצנה. חייב להופיע ב־`scenes` |
| `body` | מערך פסקאות. `{param}` הוא מציין מקום לערך |
| `keywords` | מילות מפתח לחיפוש |

## scenes

| שדה | תיאור |
| --- | --- |
| `title` | כותרת הגיליון וכותרת הנוסח |
| `rules` | סדר הסעיפים בסצנה. כל סעיף כאן חייב להצביע חזרה על הסצנה הזו |

## parts: תוכן העניינים

```
parts: [
  { id: "חלק ג'", title: "בטיחות אש בבניינים",
    groups: [ { title: "פרק ב׳ סימן א׳: דלתות" | null,
                sections: [ { ref: "3.2.1.3", title: "..." } ] } ] }
]
```

ב־MVP הקבוצות היו פריטים מסוג `['g', label]` בתוך רשימה שטוחה. כאן הן אובייקט עם כותרת, וקבוצה בלי כותרת (`title: null`) היא רשימה ישירה של החלק. סעיף בלי רשומה ב־`rules` מוצג כ"טרם הוזן".

## fixtures ו־sceneFixtures: גיאומטריית רקע

אלה לא ערכים רגולטוריים. הם המידות של המודל לדוגמה: גודל מגרש, עובי קירות, גובה אדם, מספר הדירות.

- `fixtures`: מה שהיה `FIX` ב־MVP. משותף לכל הסצנות.
- `sceneFixtures.<scene>`: מספרים שב־MVP היו כתובים בתוך קוד הסצנה (למשל שטח רצפה לדוגמה של 12 מ״ר בסצנת החלון). הם הועברו לכאן כדי שבקוד הסצנות לא יישאר אף מספר מידה.

## synonyms

מערך של קבוצות מילים נרדפות לחיפוש. כשמילה מקבוצה מסוימת נמצאת בשאילתה, כל הקבוצה מתווספת לחיפוש.

## שלמות: בדיקות בזמן בנייה

הבדיקות ירוצו ב־`npm run validate` (zod ובדיקות הצלבה), לפני `tsc` ו־`vite build`:

1. כל `{key}` בגוף של `rules` קיים ב־`params`.
2. כל `params[*].rule` קיים ב־`rules`.
3. כל `rules[*].scene` קיים ב־`scenes`, וכל `scenes[*].rules` מצביע חזרה על אותה סצנה.
4. כל מפתח ב־`rules` מופיע ב־`parts`.
5. אין מספר סעיף כפול ב־`parts`.
6. `verified: true` מחייב `source`.
7. **בקוד:** אף קובץ ב־`src/scenes/` לא מכיל ליטרל מספרי שאינו 0, 1, 2 או ‎-1 (או חצי, לחלוקה). הבדיקה סורקת את הקבצים.

מצב נוכחי: בדיקות 1 עד 6 עוברות על הקובץ שחולץ (14 פרמטרים, 11 סעיפים עם תמצית, 7 סצנות, 61 סעיפים בתוכן העניינים).

## Supabase

לא בשימוש בגרסה הראשונה. אם יידרש יומן אימות (מי אימת, מתי, מול איזה נוסח), הוא יהיה באותו פרויקט Supabase, ב־schema נפרד בשם `takanot_merhav`, וקובץ ה־JSON יישאר מקור האמת לבנייה.
